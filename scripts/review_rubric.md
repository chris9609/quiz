# 候補レビューの採否基準

`data/candidates.json` の `status: pending` を採用（approved）／見送り（rejected）に振り分けるときの基準。
レビューは Claude（Claude Code のセッション）が行う。人が判断していた頃の基準を明文化したもの。

判定時は `status` と一緒に `review_reason` を書き、あとから理由を追えるようにする。

## 手順（必ず両方やる）

1. **事実の裏取り** — `source_url` の記事（`wikipedia_source.fetch_extract(source_title)` で導入部が取れる）を読み、
   問題文に書かれた固有名詞・数字・年・関係性を一つずつ照合する。
   資料を渡して生成しているとはいえ、4B モデルは要約の過程で「誰が誰に何をした」を取り違えることがある。
   **「有名だから合ってるだろう」で通さない。** 照合した根拠を `review_reason` に一言残す（例:「三冠阻止・黒い刺客は出典と一致」）。
2. **下の採否基準で判定** — 裏取りが通った上で、マニアック度・ジャンル・日本語・一意性を見る。
3. **必要なら問題文を手直しする** — 中身は良いのに言い回しだけが硬い候補は、見送らずに直して採用してよい
   （判定 JSON の `question` に手直し後の文を入れる。元の文は `original_question` に残る）。

## 手直ししてよい範囲

- 文末の整え（「〜守護神に名前を起源とする？」→「〜守護神にちなんで名付けられた惑星は？」）、語順、冗長な語の削除
- 早押しで冒頭から当てられるよう、ヒントの順番を「大きな特徴 → 決め手」に並べ替える

**やってはいけない**: 出典にない事実を足す／答えを変える／別の問題に作り替える。
手直し後の文も裏取りと機械チェック（文字数・答えの露出・1文・疑問形）の対象。`review_with_claude.py` が機械チェックで弾く。

## 見送りにするもの

1. **答えがマニアックすぎる** — 早押しクイズとして、一般的な知識で答えに辿り着けないもの。
   目安: 答えを聞いて「ああ、あれね」とならないもの。
   例: 「江戸城跡のヒカリゴケ生育地」「器楽的幻覚」（無名の短編小説）
2. **ジャンルが合わない** — 18禁ゲーム、成人向け作品、特定の宗教・政治的主張に踏み込むもの。
3. **日本語が不自然** — 疑問文として成立していない、文末が変。手直しで直る程度なら直して採用する。
   例: 「〜に名前を起源とする？」（→ 手直し対象）
4. **問題文だけでは答えが一意に絞れない** — 複数の答えが成り立つ。
5. **事実誤認** — 出典と照合して一致しない記述が一つでもあるもの。出典で確認できない記述も同じ扱い。

## 採用するもの

- 上の5つに当てはまらず、「知っている人ならわかる」レベルの一般教養・雑学・スポーツ・科学・地理・歴史・有名作品。
- 問題文が長めでも、早押しなので冒頭で当てられる構造になっていれば良い（ヒントが徐々に具体化する形が理想）。

## 迷ったとき

- マニアックかどうかで迷ったら見送る。
- 日本語が少し硬い程度なら採用してよい。

## 機械的に落とすもの（ここでは判定しない）

文字数・答えの露出・多文構成・読みの有無・重複・天然記念物系タイトル（〜生育地/自生地/生息地）は
`generate_quiz.py` の `validate()` で落ちるので、レビューには来ない。
